# Porting to the Samsung Galaxy A21s (SM-A217F, Exynos 850)

**Status (2026-11-01): scaffold only. Nothing here has run on the phone.** The shim and
device-tree generator build for the A21s; every address below is tagged with where it came
from. Anything tagged UNVERIFIED must be read off the real phone before it is trusted.

Sources: upstream Linux `exynos850.dtsi` (SoC-level, "mainline"), the published phone spec
("spec"). The phone's own vendor device tree can differ from mainline.

## What differs from sweet (SM7150)

| Area | sweet | A21s | Source | Work |
| --- | --- | --- | --- | --- |
| CPU | 6xA55 + 2xA76, MPIDR `core<<8` | 8xA55, MPIDR 0-3 and 0x100-0x103 | mainline | ADT done (`mkadt.py --platform a21s`) |
| Interrupt controller | GICv3 (ICC sysregs, redistributors) | **GIC-400 = GICv2** at GICD `0x12a01000`, GICC `0x12a02000` | mainline | **kernel rewrite** (step 3) |
| Timer PPIs | vtimer INTID 19 | vtimer 27 (PPI 11), ptimer 30 (PPI 14) | mainline | ADT + shim done |
| Firmware calls | PSCI via smc | PSCI 1.0 via smc | mainline | none expected |
| Boot | `fastboot boot` | **no fastboot boot**: flash BOOT via Odin/Heimdall, download mode = Vol Down + Vol Up + USB | project porting page, device wiki | step 1 |
| Storage | UFS (Qualcomm host, `sweet_ufs.c`) | DesignWare MMC `0x12100000` is the SoC's eMMC host; **whether the A21s uses eMMC is UNVERIFIED** | mainline | new driver (step 4) |
| Display | 1080x2400 FB @ `0x9c000000` left by ABL | 720x1600 (spec); FB address UNVERIFIED, and Samsung's bootloader may switch the panel off | spec | step 2, 5 |
| Touch / keys / PMIC / battery | Goodix on GENI I2C, PM6150 over SPMI, RPMh | unknown chips, none of these buses | - | new drivers (step 6) |
| USB | DWC3 behind the Qualcomm wrapper (VBUS override in QSCRATCH) | Exynos DWC3 + its own PHY, different wrapper | - | rewrite patches 0072-0081 (step 7) |
| RAM | ~3.95 GiB | 2, 3, 4 or 6 GB depending on model | spec | check your unit has 4 GB or more |

About 66 of sweet's 81 kernel patches are SoC-independent (per the project's porting page),
about 10 need new addresses, and the Qualcomm drivers are the ones above that get replaced.

## Steps, in the order they can come alive

0. **Collect + back up.** With the phone in a recovery with `adb root`:
   `tools/a21s-collect.sh -b a21s-dump` dumps the live FDT, `/proc/iomem`, storage type,
   framebuffer, input/I2C/USB facts, and copies boot/vbmeta/dtbo and Samsung's calibration
   partitions. The folder holds IMEI/calibration data and is git-ignored. Nothing else in this
   document should start before that backup exists and is checksummed.
1. **Get code running.** Needs an unlocked bootloader (OEM unlock; this trips Knox
   permanently) and a flashed BOOT partition holding the shim image, with `vbmeta`
   verification disabled. Build:
   `PLATFORM=a21s A21S_FB_BASE=0x... A21S_BOOTIMG_ARGS="$(unpack_bootimg --boot_img stock-boot.img --format=mkbootimg)" shim/build.sh`.
   Boot header version, offsets and whether the `SEANDROIDENFORCE` trailer is required are
   UNVERIFIED (`A21S_SAMSUNG_FOOTER=1`). A bad flash is recoverable by re-flashing the stock
   boot image from download mode. **Each flash needs the owner's go-ahead (AGENTS.md).**
2. **A picture.** First test: the shim paints the framebuffer (`con_clear`). Take the address
   from `fb.txt`/`iomem.txt`/`display.txt`. If the screen is dark after Samsung's bootloader
   hands over, a DECON/DSIM display driver comes before anything else.
3. **GICv2 in XNU.** Sweet's patches use GICv3 sysregs. The places to port: `sleh_irq`
   (`ICC_IAR1_EL1`/`ICC_EOIR1_EL1` become `GICC_IAR`/`GICC_EOIR`), `pe_init_fiq` (enable via
   `GICD_CTLR` and `GICC_CTLR`/`GICC_PMR`, banked per-CPU GICD registers for PPIs/SGIs, no
   redistributor wake), IPIs (`GICD_SGIR` instead of `ICC_SGI1R_EL1`), and the per-CPU init in
   the SMP patches 0018 and 0065. The shim already has a GICv2 `irq_handler` (`shim.c`).
   The ADT `gic` node is `arm,gic-400` with `reg = <GICD GICC>`.
4. **Storage.** Replace `bsd/dev/sweet_ufs.c` (patches 0028, 0030, 0034, 0069) with an
   eMMC/DWMMC block driver exposing the same interface; the iOS HFS+ root goes into `userdata`.
   If the A21s turns out to be UFS, it is the existing driver pointed at the Exynos host.
5. **Display.** iOS is presented as an iPhone X (1125x2436). The panel is 720x1600, so the
   blit in patches 0046/0056/0061 needs a downscale instead of sweet's centered 1080x2400 crop.
6. **Input and power.** Identify the touch IC, the key GPIOs and the PMIC from `input.txt`,
   `i2c.txt`, `power.txt`; replace `sweet_touch.c`, `sweet_keys.c`, `sweet_rpmh.c` and the battery
   service.
7. **USB and live log.** Rewrite 0072-0081 for the Exynos DWC3; until then logs come off the
   phone through recovery.

## Generating the device tree

```
tools/mkadt.py out.adt --platform a21s --mem-base 0x... --mem-size 0x... --fb-base 0x... --dump
```

`--mem-base/--mem-size` is the RAM range XNU may own: take it from `iomem.txt` ("System RAM")
minus every Samsung reserved region. There is deliberately no default.
